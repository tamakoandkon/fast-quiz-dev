# 已有账号跨租户与预生成试卷领取

更新：2026-10-14。基于合并 PR #15 后的 `main` / `ba78b89`；本次不部署生产、不更换凭据、不修改数据库模型。

## 已有账号加入另一租户

系统管理员打开“租户管理”，在目标租户行点击“添加已有账号”，输入已注册的完整用户名并确认。账号下次读取“我的租户”即可看到新空间；不需要重新注册或修改密码。

- `POST /tenant/{tenantId}/members`，JSON 为 `{"username":"已有用户名"}`，成功返回该用户 DTO。
- 服务端先验证默认系统租户下的 `SystemAdmin` 权限，再查目标租户与精确用户名。不向普通用户或普通租户管理员提供全局账号枚举/搜索能力。
- 只增加成员关系，保留原租户关系、全局账号与密码，不自动分配管理员或其他角色；需要角色时仍走原有授权流程。
- 重复加入返回成功，数据库复合成员键避免并发重复；其他数据库错误不伪装为成功。加入后清理目标租户的权限缓存。
- 旧的用户映射 POST 路由仍不对外开放；旧删除路由与本次新加入端点区分，避免悄悄复活未经授权的历史接口。

## 预生成与领取

1. 管理员创建抽题规则及试卷样本。
2. 在“试卷管理 → 对应模板 → 样本列表”点击样本行的“批量生成”，输入份数；下方“待领取试卷”显示库存，可刷新和加载更多。
3. 发布模板后，符合资格的考生在“考试中心”点击“领取预生成试卷”，系统绑定当前考试的一份未分配试卷，并开始答题。
4. 暂时离开可从“我的考试”继续。库存为空、已有进行中考试、次数耗尽或不符合资格时显示明确错误，不偷偷另建一份卷。

### API 契约

以下路径位于 `/tenant/{tenantId}/quiz-template` 下：

| 方法与相对路径 | 行为 |
| --- | --- |
| `POST /{templateId}/quiz-attempt/batch` | 命令数组，每项包含 `quizSnapshotId`、`count`；每批合计 1–100 份，每项为正整数，204 成功 |
| `GET /{templateId}/quiz-attempt/prebuilt?Count=…&Cursor=…` | 考试管理员读取未分配且 Pending 的库存；每页 1–100 条、游标向后分页，只返回试卷及快照 ID |
| `POST /{templateId}/quiz-attempt/claim` | 当前考生自动领取该考试的一份库存，返回本人试卷 DTO；不会返回题目答案 |
| `POST /quiz-attempt/{attemptId}` | 恢复原来注释的指定 ID 领取接口；身份只取当前登录用户，成功 204 |

管理员生成/读取库存需要 `QuizAttempt` 权限及当前租户成员关系。领取不需要阅卷或管理权限，但必须验证当前租户、模板归属、发布状态、开放时间、指定组织、活动考试与次数限额。抢到的试卷始终绑定请求本人，不能通过提交另一个 userId 代领。

原“开始考试”的动态创建入口保留；两种入口共用资格和次数校验。本次不增加管理员指定他人分配，也不增加强制“只能使用预生成库存”的考试模式。

### 事务与并发

- 每批命令、每份试卷与题目写入同一事务；使用别的模板快照、缺失快照、空试卷或中途失败时整批回滚。
- 普通创建、批量生成和领取都使用 `IQuizUnitOfWork.ExecuteForTemplateAsync`：在数据库事务内对模板行做无值变更 UPDATE 取得锁，而非进程内互斥。
- 指定 ID 领取在锁内重新读取试卷状态；自动领取在锁内选择候选并绑定。不同请求不能覆盖先领取人的归属。
- 普通创建与领取共用模板锁，防止同一考生通过两个入口并发绕过未结束考试与次数限额。
- SQLite / PostgreSQL / MariaDB 仓储均实现相同的库存查询，模型未变更。MariaDB 的历史升级迁移缺口仍按原重构清单跟踪，不借此宣称已验收所有 provider。
- 此处保护创建/领取，不解决已知的“提交业务事务后、Hangfire 入队前”崩溃窗口；outbox 与多实例故障演练仍为独立待办。
