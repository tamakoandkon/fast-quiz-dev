# 前端加载优化

## 本轮调整

- 导航仅在鼠标悬停或键盘聚焦时预取，不因可见菜单、卡片一次性拉取多个页面。
- 试卷详情、个人资料弹窗在打开时才加载和挂载；保留原有 Markdown 渲染行为，不引入新的 HTML 渲染或绕过清洗。
- 个人资料按当前登录会话复用，同一时间合并请求；显式刷新仍可用。登出和切换账号清除缓存、权限，丢弃旧会话的迟到响应。
- 工作空间初始化不重复拉取已恢复的个人资料；权限请求不再等待第二次资料请求。
- 运行配置在后台读取，不阻塞登录界面渲染；API 请求仍等待配置，以兼容自定义 API 地址。配置失败或超过 3 秒时回退同源 `/api`。

## Nginx 配置

Nuxt 构建已输出 `.gz`、`.br`，但静态服务器不会自动使用它们。将
[压缩配置片段](../Deploy/nginx-static-performance.conf) 放入本应用的 `server` 块，或复制到私有部署配置后 `include`。
需要 Nginx 编译了 `--with-http_gzip_static_module`。不要全局修改其他站点。

先备份本应用配置，执行 `nginx -t`，成功后平滑 reload。验证 JS、CSS 的实际 GET
响应有 `Content-Encoding: gzip`、`Vary: Accept-Encoding`，无压缩协商的请求仍返回原文件。
不能仅看 HTML 压缩或 `.gz` 文件是否存在。

继续保留哈希资源的一年 immutable 缓存、HTML 的重新验证和 `config.json` 的 `no-store`。
本轮不更改监听端口、TLS 或数据库。HTTP/2 需单独配置受信任的 HTTPS 入口，不在现有明文入口强行开启。

## 回归与发布

```bash
cd FastQuiz.Frontend.Server
npm test
npm run typecheck
npm run build
npm run check:loading
```

浏览器验证：登录 → 租户概览 → 考试中心 → 详情 → 关闭重开；个人设置首次打开、修改后刷新资料；
登出、重新登录与租户切换。验证关闭的详情不会预加载完整编辑器，运行配置覆盖仍生效。
所有业务写入测试使用隔离数据或模拟 API，不在生产创建测试试卷或账号。

### 隔离对照记录（2026-10-14）

同一浏览器、同一模拟账号和 API，在两个独立本机 origin 直接刷新租户概览；禁用 HTTP 缓存，
配置响应延迟均为 250 ms、API 均为 30 ms。旧构建原样传输，新构建协商预压缩 gzip。
页面内 Performance API 在 load 后 1.8 秒采样（不含 HTML 主文档）：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 资源响应体传输量 | 1,974,851 B | 233,909 B |
| 资源请求数 | 99 | 36 |
| JS 请求数 | 90 | 29 |
| 获取个人资料 | 2 次 | 1 次 |
| 首次进入时加载完整编辑器 | 是 | 否 |

这验证传输量减少约 88%，不代表公网完整加载时间降低 88%。本机首屏不能替代生产登录态测速。
浏览器验证了考试详情首次打开、关闭重开、Markdown 展示、个人设置首次打开及修改用户名后刷新显示。

前端发布到新目录，保留旧内容哈希资源，以兼容已打开的页面；原子切换前端与压缩配置，失败恢复旧路径、配置。
后端未改动时不重启后端，也不执行迁移。不要用旧数据库备份覆盖正在产生的新业务数据。

测速应注明页面、登录态、缓存状态、协议、压缩后传输大小及测试位置。
静态资源体积下降不等于完整页面耗时同比下降，不能将单文件 curl 耗时写成已登录页面的首屏时间。
